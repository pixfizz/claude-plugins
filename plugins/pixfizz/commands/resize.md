Load the `template-resize` skill from this plugin and run its workflow end to end.

Ask for the export and the target size — or the size list, for a range — if not supplied. Read the export first and report the reference graph before changing anything: on a range build the seed answers most of the intake, so only ask about what it cannot tell you.

Do not skip the proof sheet. Never apply a `stretch` transform, auto-fix a cover size, or invent a wrap depth, category, price or style token without explicit instruction. Audit any supplied pricing for rows where a larger product costs less, and report them without changing the numbers. State the id and `layout_id` behaviour from `references/import-behaviour.md` in the handover.
